# GitHub + Vercel

Исходники публикуются в приватном GitHub-репозитории. Vercel собирает Next.js по main. PostgreSQL — отдельная облачная база, рекомендуемая конфигурация: Neon в регионе Frankfurt рядом с функциями fra1. Платные ресурсы без отдельного разрешения не подключаются.

Production environment: DATABASE_URL (облачный PostgreSQL), BETTER_AUTH_SECRET (новый случайный секрет), BETTER_AUTH_URL (постоянный HTTPS-адрес приложения). LOCAL_DEMO_PASSWORD, локальный POSTGRES_PASSWORD и BACKUP_KEY в Vercel не передаются.

Preview не должен подключаться к базе с личными данными: использовать отдельную ветку/базу либо не предоставлять ему production-переменные. Не применять production-миграции автоматически при каждом preview build.

До production deployment: создать отдельную пустую облачную базу, выполнить prisma migrate deploy с её адресом. Локальная база не заменяется и .env не переписывается. При переносе копируются только личные пользователи, credential-аккаунты с хешами и их Workspace; демо и прежние сессии не переносятся. После переноса проверить количества и содержимое, затем вход по HTTPS.

Vercel не запускает Docker Compose и постоянный backup-процесс. Локальный зашифрованный бэкап остаётся локальным; облачное восстановление зависит от выбранного тарифа PostgreSQL и отдельного расписания экспорта. Нельзя заявлять, что ежедневный compose-backup работает в Vercel.

После публикации компьютер можно выключить. На iPhone открыть production URL в Safari, войти своим аккаунтом, «Поделиться» → «На экран Домой».
