# Эксплуатация

## Локально

Адрес http://localhost:3000, отдельный PostgreSQL на 127.0.0.1:5440. Данные переживают перезапуск в Docker volume personal-finance_finance_data. Не выполнять `docker compose down -v`, если нужны данные.

Обычный запуск: `docker compose up -d`, `pnpm run dev`. Остановка приложения — Ctrl+C в его терминале; базы — `docker compose stop`.

## Резервные копии

BACKUP_KEY — 64 hex-символа, хранить отдельно в менеджере паролей. Копия без ключа невосстановима. Команда `node --env-file=.env scripts/backup.mjs --docker` сохраняет AES-256-GCM копию в backups, удаляя собственные файлы старше 30 дней. Реальные файлы и ключи не коммитятся.

Проверка: `node --env-file=.env scripts/backup.mjs --docker --restore backups/ИМЯ.enc finance_restore_check`. Создаёт новую базу и отказывается заменять активную. Сравнить записи, остатки и версии, затем удалить только проверочную базу через администратора PostgreSQL. Автоматическая проверка — tests/integration/backup.test.ts.

Локально автоматическое ежедневное расписание не зарегистрировано. Production compose содержит отдельный ежедневный backup-сервис; его ошибки видны по ненулевому выходу и логам. Дублировать копии за пределами сервера до ввода реальных данных.

## Облачная поставка

Не выполнена: нет сервера/домена пользователя. Подготовлен контейнер для собственного Linux VPS с Docker Compose; аренду и домен выбирать до оплаты. Облачная доступность и фактическое расписание бэкапов ещё не проверены.

1. Настроить DNS домена на сервер, разрешить 80/443. В `.env` сервера задать DOMAIN, POSTGRES_PASSWORD, BETTER_AUTH_SECRET, BACKUP_KEY. Удалить LOCAL_DEMO_PASSWORD.
2. `docker compose -f compose.production.yaml build`.
3. `docker compose -f compose.production.yaml up -d db`.
4. `docker compose -f compose.production.yaml run --rm app node node_modules/prisma/build/index.js migrate deploy`.
5. `docker compose -f compose.production.yaml run --rm -it app node node_modules/tsx/dist/cli.mjs scripts/create-owner.ts`.
6. `docker compose -f compose.production.yaml up -d`.
7. Проверить вход, операции, импорт и синхронизацию на компьютере и iPhone. В Safari: «Поделиться» → «На экран Домой».

Для обновления сначала резервная копия, затем сборка, migrate deploy и перезапуск app. Для отката вернуть предыдущий образ приложения; схему БД автоматически не откатывать, сначала оценить совместимость. Активную базу восстанавливать только после ручного сравнения с отдельной восстановленной базой.

## Доступ и удаление

Регистрация через публичный API отключена. Все данные разделены по user.id сессии, клиентский ownerId не принимается. Изменения требуют точного origin и версии рабочей области. При конфликте форма остаётся открытой: проверить обновлённые данные и повторить.

Экспорт и удаление доступны в настройках после входа не более 10 минут назад. Удаление аккаунта каскадно удаляет рабочую область, учётные записи и сессии. Данные остаются в зашифрованных бэкапах до истечения срока хранения 30 дней. После восстановления старой копии повторно применить запросы на удаление, поступившие после неё.

## Известные границы

Физический iPhone, Safari и облачный HTTPS проверяются отдельно от Chromium с мобильной эмуляцией. СМС, пуши, автоматические переводы, совместный бюджет, точный процентный прогноз и полноценный офлайн вне первой версии. Реальную банковскую выгрузку нужно проверить по обезличенному примеру.
