# Personal Finance Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.
> Эти навыки не представлены в текущем каталоге. При исполнении сначала проверить доступность; если их нет, не заявлять об их использовании. Сейчас разрешено только планирование, выполнение задач не начинать.

**Goal:** Личное приложение, которое объединяет бюджет месяца, импорт Т-Банка, контроль долгов, накопления и анализ необязательных расходов.

**Architecture:** Одна адаптивная PWA и серверное приложение с реляционной базой. Денежные расчёты — отдельные чистые функции; изменения операций, резервов и импорта проходят серверные транзакции. Все записи принадлежат пользователю, интерфейс не обращается к базе напрямую.

**Tech Stack:** Предложение исполнителя: TypeScript, Next.js, PostgreSQL, Prisma, Zod, Recharts, Vitest и Playwright; Docker Compose для локальной базы. Проверить актуальные совместимые версии по официальной документации при начале реализации, зафиксировать lockfile. Способ входа — email/пароль с готовой поддерживаемой библиотекой сессий, а не собственной криптографией. Облачный провайдер и библиотека входа выбираются в задаче 0 после проверки доступности и стоимости; до неё зависимости не устанавливать.

## Global Constraints

- «Разработка не разрешена.» Требуется отдельное распоряжение пользователя начать.
- «Все суммы первой версии в рублях, хранятся с точностью до копейки.»
- «Ожидаемый доход 200 000 ₽ редактируется и служит планом, а не доступными деньгами.»
- «Переводы между своими счетами не доход и не расход.»
- «Если денег не хватает на обязательства, предложение накоплений равно нулю с объяснением.»
- «После закрытия всех долгов предлагается применить заранее заданный повышенный процент; без подтверждения настройки не меняются.»
- «Первая версия работает при наличии интернета; полноценная работа без сети отложена.»
- «Банковские пароли, коды и полные реквизиты карт не запрашиваются.»
- «В первую версию входит один подтверждённый формат выписки Т-Банка.»
- Часовой пояс пользователя Europe/Moscow, даты операций — локальные календарные даты; суммы в целых копейках, проценты — целые базисные пункты. Никаких расчётов денег через float.
- Внешний вид ещё не выбран: согласовать статические макеты до реализации страниц. Не подменять неизвестный формат выписки вымышленным.
- После каждого законченного этапа — относящиеся к нему проверки, независимый обзор по loop-code-review перед коммитом изменений кода. Не выдумывать автора Git; коммит возможен после настройки имени и почты владельцем.

## Review Focus

1. Двойное подтверждение импорта или распределения из двух вкладок: один финансовый результат (задачи 2, 4, 5).
2. Изменение или удаление уже связанного платежа: остатки, долги и резервы пересчитаны атомарно (задачи 2–4).
3. Покупка по карте перед обновлением банковской суммы: резерв не теряется и не удваивается (задача 3).
4. Смена месяца при неполной истории: обязательства сохраняются, свободная сумма предварительная (задачи 4, 6).
5. Возврат прошлого месяца, одинаковые реальные покупки, неверная кодировка файла: не искажаются расходы и записи (задачи 2, 5, 6).

## Файлы и интерфейсы

Все пути ниже относительны корню проекта. Существующего кода нет, создавать файлы только при разрешённом выполнении.

- `src/domain/types.ts`: `Money = bigint` (копейки), `LocalDate = string` (проверенный YYYY-MM-DD), `Id = string`; DTO передают деньги десятичной строкой.
- `src/domain/ledger.ts`: операции и остатки.
- `src/domain/debts.ts`: графики, связи погашений, резерв карты.
- `src/domain/budget.ts`: планы, горизонт, резервы, распределение.
- `src/domain/analytics.ts`: дневные и недельные показатели.
- `src/domain/import.ts`: нормализованные строки, сверка и повторы.
- `src/server/auth.ts`, `src/server/db.ts`, `src/server/services/*.ts`: сессии, база и транзакционные команды с обязательным `ownerId` из сессии.
- `src/server/import/tbank.ts`: единственный подтверждённый адаптер формата банка.
- `prisma/schema.prisma`, `prisma/migrations/`: модель и миграции.
- `src/app/(private)/{overview,transactions,plan,analytics,debts,cushion,accounts,settings}/page.tsx`: восемь страниц; `src/app/(private)/layout.tsx`: защищённая оболочка.
- `src/components/`: общие поля денег/дат, навигация, диаграммы и таблицы. Формы предметных разделов находятся в `src/features/{ledger,budget,debts,cushion,import}/`.
- `tests/domain/`, `tests/integration/`, `tests/e2e/`: денежные правила, база/изоляция, сквозной сценарий.
- `docs/decisions/`: поставка, импорт и правила расчётов; `docs/mockups/`: согласуемые статические макеты без рабочего приложения.

Постоянные команды проекта после задачи 1: `npm run test -- <file>` для Vitest, `npm run test:integration`, `npm run test:e2e`, `npm run typecheck`, `npm run lint`, `npm run build`.
